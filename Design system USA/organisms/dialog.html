Modal

Janela que interrompe a página para pedir uma decisão, e some com a resposta. Se não há decisão a tomar, use Toast; se o conteúdo é uma segunda tela para percorrer, use Drawer.

  • Classe base .yb-dialog

Como se parece

Os três tipos, abertos

1 · Destrutivo — a ação some algo

Remove from cart?

Kit Sealant Fashion Gold — 500g / 17.6 fl oz will be removed from your cart.

2 · Confirmação — a ação segue em frente

Apply coupon SUMMER20?

It replaces WELCOME10, already on this order. Only one coupon per order.

3 · Formulário — o corpo é o formulário

Write a review

Only to confirm the purchase. It is never published.

Funcionando

Três tipos, um componente

A folha não tem variante de modal: os três são a mesma .yb-dialog, e o que muda é o pé. Destrutivo leva a ação em --danger e a saída em --ghost; confirmação troca o vermelho pelo --primary; formulário não tem pé — o .yb-dialog__body é o <form>, e o botão de enviar mora dentro dele.

Modal de um botão só é aviso, e aviso não interrompe: é Toast.

É <dialog> nativo

Foco preso, Esc e backdrop vêm do navegador. O JS só abre, fecha no clique fora e devolve o foco a quem abriu — sem isso o leitor de tela volta ao topo da página depois de fechar.

Os três acima estão open e em fluxo, para caberem na mesma tela. O botão acima abre um de verdade, com véu e foco preso.

No celular o pé inverte

Abaixo de 520px o .yb-dialog__foot vira column-reverse com botões de largura cheia: a ação principal fica embaixo, onde o polegar alcança, e continua sendo a primeira na ordem do teclado.

Anatomia e API

1 · Destrutivo — a ação some algo

Remove from cart?

2 · Confirmação — a ação segue em frente

Apply coupon SUMMER20?

3 · Formulário — o corpo é o formulário

Write a review

Only to confirm the purchase. It is never published.

  1. Button — O controle que dispara uma ação. Uma ação primária por tela: se há duas, uma delas não é primária.
  2. Select — Campo de escolha com o rótulo dentro da caixa, que abre o seletor nativo do sistema. Mesmo campo do Input, para quando a resposta já está escrita.
  3. Textarea — Campo de várias linhas com o rótulo dentro da caixa, que cresce na vertical. Mesmo campo do Input, para mensagem, nota de presente ou avaliação.
  4. Input — Campo de uma linha com o rótulo dentro da caixa, que sobe quando a pessoa digita. Leva dica e erro em texto; serve para nome, e-mail, CEP, senha.

De que a peça é feita, o que ela aceita e os tokens que consome — estes do mais específico desta peça para o mais compartilhado com o resto do sistema. Tudo lido da folha de estilo e do HTML a cada build: se estiver errado aqui, o errado é o código.

Faça / não faça

✓ Faça

Dialog nativo, com título ligado e foco devolvido a quem abriu.

✕ Não faça

Div com overlay: o foco continua correndo pela página atrás, Esc não fecha e o leitor de tela lê o conteúdo escondido.

Acessibilidade

  • É <dialog> nativo aberto com showModal(): o foco fica preso dentro, Esc fecha e o resto da página vira inerte — três coisas que a versão em <div> quase nunca acerta.
  • Ao fechar, o foco volta para o botão que abriu. Sem isso a pessoa que navega por teclado é devolvida ao topo do documento.
  • O título é ligado por aria-labelledby, para o leitor de tela anunciar o que abriu.
