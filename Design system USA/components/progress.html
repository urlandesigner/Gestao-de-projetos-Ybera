Progress bar

Espera com fim conhecido. Sem número para anunciar, use a variante indeterminada.

  • Classe base .yb-progress
  • Modificadores 3
  • Elementos 4
  • Estados 0
  • Tokens 10
  • Comportamento só CSS

Como se parece

Free shipping — $12.10 to go

Order placed → Delivered

Profile complete

Only 4 kits left at this price

Loading reviews

Indeterminada não tem aria-valuenow

Declarar um número que ninguém sabe é pior do que não declarar: o leitor de tela anuncia "12 por cento" de uma espera que pode ter acabado. Sem o atributo, ele anuncia "ocupado" — que é a verdade.

Sem movimento, a faixa some

Em prefers-reduced-motion uma faixa parada em 40% mentiria sobre o progresso. Ela vira a pista inteira esmaecida: presença sem promessa.

Anatomia e API

Lido da folha a cada build. Se faltar alguma coisa aqui, falta na folha.

Modificadores

.yb-progress--indeterminate .yb-progress--lg .yb-progress--sm

Elementos

.yb-progress__fill .yb-progress__fill--danger .yb-progress__fill--success .yb-progress__fill--warning

Estados que a folha trata

Nenhum: o componente não muda de aparência por interação.

Marcação

Extraída da primeira demonstração acima — é o mesmo HTML que renderizou ali, não um exemplo escrito à parte.

Acessibilidade

  • Com valor conhecido: role="progressbar" com aria-valuenow, valuemin e valuemax, mais aria-label dizendo progresso de quê.
  • Sem valor conhecido, a variante indeterminada não declara aria-valuenow — número inventado é pior que número ausente.
  • Sob prefers-reduced-motion a faixa indeterminada para de andar e some: uma barra parada em 40% mentiria sobre o progresso.

Faça / não faça

✓ Faça

Valor anunciado junto com o que ele mede.

✕ Não faça

Barra sem papel nem valor: quem não a vê não sabe que existe progresso.
