Skeleton

Só para carregamento real. Skeleton eterno é pior que spinner: promete conteúdo que não chega.

  • Classe base .yb-skeleton
  • Modificadores 6
  • Elementos 0
  • Estados 0
  • Tokens 7
  • Comportamento só CSS

Como se parece

O skeleton imita o layout, não o conteúdo

Duas linhas de texto e um preço, na mesma ordem e altura do card real — por isso não há salto quando o conteúdo chega. O brilho respeita prefers-reduced-motion.

Em 375px

Viewport de verdade, num <iframe> — e não um quadro estreito. @media consulta a viewport: encolher uma div entregaria a peça fina com o CSS de desktop, que foi como a gaveta do carrinho já apareceu com 222px fingindo estar quebrada.

Anatomia e API

Lido da folha a cada build. Se faltar alguma coisa aqui, falta na folha.

Modificadores

Elementos

Peça de um elemento só: não há partes internas com classe própria.

Estados que a folha trata

Nenhum: o componente não muda de aparência por interação.

Acessibilidade

  • A área que carrega declara aria-busy="true". O esqueleto é sinal visual; sem o atributo, quem usa leitor de tela ouve silêncio e conclui que a página acabou.
  • Os blocos são aria-hidden="true": retângulos cinzas não têm nada a dizer.
  • Sob prefers-reduced-motion o brilho para. Ele é a única animação da página que roda em loop indefinido.

Faça / não faça

✓ Faça

Região marcada como ocupada, blocos escondidos do leitor.

✕ Não faça

Sem aria-busy, o carregamento é invisível para quem não vê a animação.
